## Idea

A decision model never writes text and never emits a tool call. It reads a state and answers closed questions (`choice`, `noul`, `score`) with calibrated probabilities. So it cannot "use the MCP tools" itself; a deterministic harness does, and the decision model is the harness's only learned part:

1. The harness builds the **state** from the user's data and request: columns and their roles, units, number of subjects, the request text, the analyses already in the Caladrius project.
2. The decision model answers the **closed questions**: which analysis (`nca`, `fit_pk1`, `fit_pk2`, `simulate`, `compare`, `not_available`); route (`iv_bolus`, `iv_infusion`, `oral`); AUC method; which parameter is asked; does the dose carry a unit (`noul`); which two analyses to compare.
3. The harness calls Caladrius with those answers and **renders the engine's result**: tables with units, sentences from templates. No generated number can exist, so the number gate is not needed on this path.

What is lost against the 27B pipeline: free explanations in French, questions outside the closed set. What is gained: no hallucinated number by construction, a model that trains on one RTX 3060, and a measurable comparison on the same benchmark with the same oracle check.

Not a replacement of the 27B pipeline: the two run side by side on the same benchmark. OptChat stays with the 27B pipeline (Apothicaire is a subclass of `optchat.Agent`); on the decision path the memory of the numbers is the Caladrius project file, and the state digest is built from it, not from a chat history. Pi Durable is dropped (both reviews of 2026-10-08 called the port premature, and this path needs no free-text loop).

## Steps

1. **Dataset.** From the 200 labelled turns of the two benchmark runs (`bench/runs/*/ex*.json`: the scripted intent of every turn is known) and from new exercises generated by `bench/make_exercises.py`, write `decision/make_dataset.py` producing rows `{state, questions, gold}` in the typed-decisions format of Unsloth. Target: a few thousand rows, split by exercise, with a held-out set never seen by any rule.
2. **Zero-shot baseline.** Liquid AI `d1-3B` (or `d1-omni-600M`) through its llama.cpp quantisation, asked the same questions with no training. Record accuracy per question and calibration (reliability table).
3. **Fine-tune.** Unsloth decision-model recipe on `Qwen3.5-0.8B` (4 GB VRAM, about 40 min on the Unsloth table; the 2B scored lower than the 0.8B there). Linux side: WSL (the human mentions a new WSL release; check the CUDA passthrough first) because Unsloth is Linux-first. Export: `save_pretrained_merged` and serve through the Unsloth Decision API from the harness (GGUF export is not documented for the head).
4. **Harness.** `decision/harness.py`: state builder, question set, Caladrius MCP calls (reuse the client of `apothicaire.py`), template rendering in French. Golden tests on three exercises.
5. **Score.** Run the 25 benchmark exercises through the harness; score with `bench/score.py` (oracle check) and report next to the 27B runs: turns correct, numbers correct, time per turn, VRAM. Then the held-out exercises.

## Completion criterion

A report `decision/runs/<date>/report.md` with, per pipeline (27B + gate, decision harness), the same three lines: oracle-correct turns / total, oracle-correct numbers / total, invalid or failed tool calls / total; plus the calibration table of the decision model on the held-out set. Synthetic data only (the rule since 2026-10-09).
