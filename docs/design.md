# Files and design choices

The files of the repository and the design choices of the client, moved unchanged from the former README.

## Files

| file | role |
|---|---|
| `apothicaire.py` | the agent: a small MCP stdio client (JSON-RPC 2.0 lines: `initialize`, `tools/list`, `tools/call`), conversion of the MCP tool schemas to OpenAI function definitions, the digest of NCA results, `Apothicaire(optchat.Agent)` which adds the Caladrius tools next to `zoom` / `read_message`, the system prompt addition, and the gate wiring |
| `gate.py` | the number gate: pure Python, no model. Its definitions (extraction, allowed set, matching rule, exemptions) are the module docstring |
| `run_exo1.py` | the scripted 4-turn French demo on exercise 1 (TD1, 10 mg oral); reports `numbers_unverified / numbers_total` per turn and in total |
| `tests/` | `test_digest.py` (golden files + schema flattening), `test_gate.py`, `test_agent_gate.py` (gate wiring with a scripted model and the real MCP server), `make_golden.py` (regenerates the goldens by hand), `golden/*.json` |
| `runs/` | transcripts (`<date>-exo1*.md`, `.json`) and the chat memory of each run (`<date>-exo1*-data/`). The exercise data is private coursework: it is read at run time and appears only here; **`runs/` is git-ignored** (the transcripts embed the CSV) |
| `bench/` | the benchmark: `make_exercises.py` (25 synthetic exercises simulated by Caladrius, `bench/exercises/<id>/data.csv` + `meta.json` with the oracle NCA), `scripts.py` (8 French turns per exercise type and the expected-answer rule of each), `score.py` (expected-number matching with the gate's rounding rule, failure taxonomy, oracle check, tool-argument audit), `run_bench.py` (runner and report), `runs/<date>/` (per-exercise records, `report.json`, `report.md`; the `*-data/` memory folders are git-ignored) |
| `data/` | the chat memory of `apothicaire.py chat` / `say` (git-ignored); `gate.jsonl` there logs the gate's counts and findings of every turn |

## Design choices

- **Tools exposed**: `zoom`, `read_message` (memory) + `data_import`, `nca_run`, `analysis_get`, `export_table`, `analysis_compare` (since 2026-10-09, Caladrius commit df87aca: b minus a, relative difference in percent and ratio of the parameters two analyses share, computed by the engine; the system prompt says that differences, percentages and ratios come from it, never from the model). The full Caladrius tool list (see "Pinned versions" in [runtime.md](runtime.md) for its size) does not fit a 12k context; `fit_run` alone is ~3 kB of schema, so fitting is left out of v0. Schemas are flattened (`$ref` inlined) and `nca_run` shows only the options `auc_method`, `start`, `lambda_z`, `quality` and `lambda_z_selection` (leave sample times out of the λz regression, or choose them; the server still accepts all of them), plus a `dose_unit` argument (the unit of the dose as the user gives it) (`to_openai` and `NCA_OPTIONS_KEPT` in `apothicaire.py`, as of 2026-10-29). The route is `extravascular`, `iv_bolus` or `iv_infusion` plus a number `infusion_duration`; the client builds the server's `{"iv_infusion": {"duration": d}}` (the 27B wrote that object as a string when the schema offered it as an `anyOf`: tool-call validity, found by the benchmark). **Static prefix: 2 434 tokens** at 2026-10-09b (system prompt + 7 tools; 2 229 with 6 tools before `analysis_compare`, 2 154 before the 2026-10-09 prompt change and the infusion route of `nca_run`), under the 2.5k budget, cached by llama.cpp.
- **`analysis_compare` is digested too**: one line per parameter, `a 148.923 h*mg/L | b 147.235 h*mg/L | difference -1.6883 h*mg/L | percent -1.13367 % | ratio 0.988663`, the parameters with no value on either side grouped under the engine's reason. Since 2026-10-19 `nca_run` called through this client carries `options.units` (time, concentration and dose units, from the worksheet and the model's `dose_unit`, `nca_units` in `apothicaire.py`) when they are known and in the engine's table, and the engine then reports the unit in the comparison; when they are not, the engine reports none and the client labels the units from the worksheet (as for the NCA digest), only when both analyses come from the same worksheet. Nothing is computed or converted.
- **NCA results are digested for the model**: a raw `nca_run` answer is ~17 kB of pretty JSON (7 kB compact: every λz candidate, the profile, ~60 parameters). The client gives the model the same values reorganised: each computed parameter as `"value unit"` (6 significant digits; units labelled from the worksheet column units, `aucpext.*` as %), the names of the parameters not calculated with the reason, the selected λz regression, the options used (auc_method, lambda_z, quality thresholds, BLQ, missing, negative, start), the flags and the engine's `flag_messages`, the `not_calculated_messages` (grouped by identical text) and the worksheet's `unit_warnings` (e.g. `mass_mismatch`, `missing_unit`). No value is converted. The full answer is kept in the tool log and the transcript. Since 2026-10-09 (after the golden tests found them missing) the digest also carries the BLQ / missing / negative / start options, `flag_messages`, `not_calculated_messages` and `unit_warnings`.
- `data_import` also accepts `path` instead of `csv` (the client reads the file); in the demo the CSV is put in the user message by Python and the model copies it into `csv`.
- The digest goes through OptChat unchanged: tool calls and results are logged, summarised and zoomable like any message.
