# Gates

How the number gate works, its known limits, and gates v2 and v3, moved unchanged from the former README.

## The number gate

Rule: every number the assistant writes must already be in a tool result (Caladrius) or in a user message (the CSV included). After each final answer `gate.check` extracts the numbers (French and English decimal marks, thousands separators, scientific notation, percentages, units attached) and looks each one up in that set; a number matches an allowed number when the allowed number, rounded to the significant digits written in the answer (at least 2), equals it. So `6,98 %` matches 6.98412 and `7,0 %` too, `6,99 %` does not. **Unit conversions and values computed by the model (differences, ratios, percent changes) are not allowed.** Exempt, not counted: integers 0 to 20 with no unit (counts), years, ISO dates, numbers after a step/label word or a list marker, `#17` message references, bare `10^k`. The assistant's earlier answers and the results of `zoom` / `read_message` are not sources.

In the agent (`Apothicaire._chat_call`): on findings, one regeneration with a `[system reminder]` message appended at the end of the messages (system prompt and tool definitions are untouched, so the cached prefix is intact; it is a `user` role message because chat templates reject a late `system` message) listing the offending numbers and the rule "quote tool values verbatim, never convert"; the better of the two answers is kept; if findings remain, `⚠ n number(s) not found in tool results: ...` is appended to what the user sees. The memory stores the answer without badge or reminder. The turn's stats carry `gate`: counts before and after the regeneration, the findings (number, position, nearest allowed value, power-of-ten hint), the first draft; `run_exo1.py` writes them to the transcript JSON.

Metric: `numbers_unverified / numbers_total`, where `numbers_total` counts the checked numbers (exempt ones excluded), per turn and in total, before the regeneration and in the answer shown.

Known limits, stated plainly:
- The gate is conservative in one direction only. A computed number with 2 or 3 significant digits can coincide with some tool number after rounding (a `−1.00 %` change passed because the tool also contains `1.00`); the counts are a lower bound. A hand review of the transcripts stays part of the protocol.
- It checks numbers, not claims: a right number attached to the wrong parameter or the wrong unit passes (units are read for the exemption rule, not compared with the tool's unit).
- A value the user typed in another format than the tool's is allowed in every plausible reading (`1,234` is 1.234 and 1234).

**Gate v2, typed rendering (experimental, `APOTHICAIRE_GATE=v2`; measured in-sample on 2026-10-17 and 2026-10-18, before the closed renderer below, see `GATE_V2.md`).** The audit of 2026-10-14 showed what set membership cannot see: a right number on the wrong parameter, a changed unit, an inverted sign, a number spelled in words, the small-integer and year exemptions, 2-digit coincidences. In v2 the model does not write tool numbers at all: it writes `{{call_3.cmax}}` (the `ref` shown at the top of each tool result) and `gate_v2.py` replaces the reference with a closed typed assertion read from the MCP `structuredContent` and checked against the tool's `outputSchema`: the engine's value with its sign, its unit and the name of the quantity, `12.3457 ng/mL [Cmax]`. Only the quantities of closed tables can be cited (the NCA parameters, the dose, the selected λz regression, the quality thresholds and named conventions, the `analysis_compare` fields); a raw JSON path or a text field such as an analysis name is never rendered. A bare number must equal, exactly, a number of the user's message; a unit, sign or arithmetic next to a reference (Markdown emphasis included), a unit elsewhere in the sentence or table column that contradicts the engine's, a quantity in words or in Unicode numerals, an unresolvable reference are replaced by a visible marker and listed in a badge (fail-closed), after the same one regeneration with a reminder. What this ensures: the digits, sign, unit and name printed for a cited quantity are the engine's. What it does not: the words the model writes around them are checked by closed pattern rules, not proven, and a wrong selection (citing `aucall` where `auclast` was asked) is visible but not rejected. v1 stays the default and is the demo gate: on 2026-10-21 (`bench/frozen/LEDGER.md`), on the development set (25 exercises, 3 seeds, in-sample), v1 passed 14 / 25 exercises (all 8 turns correct on every seed) and 583 / 600 turns, v2 6 / 25 and 562 / 600, so v2 is descriptive only. A third variant, gate v3 (v2 plus a grammar on the one regeneration, `bench/GRAMMAR_ARM.md`), was killed on 2026-10-24 by its pre-registered rule at 557 / 600 turns on the same set; it stays behind `APOTHICAIRE_GATE=v3`, development tier only. Spec, resolution rules, guarantees and what remains: `GATE_V2.md`. Tests: `tests/test_gate_v2.py` (synthetic payloads; the audit's blind spots as mutation cases that v1 accepts and v2 rejects; the red-team probes of 2026-10-19 as mutation tests; prefix budget), `tests/test_agent_gate_v2.py` (wiring with the real server). Benchmark: `python bench/run_bench.py --gate v2`.
