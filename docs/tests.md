# Test suite

What the test suite holds and how it runs, with the counts of each file, moved unchanged from the former README.

## Tests

712 `unittest` test methods in `tests/` as of 2026-10-29 (`grep -c 'def test_' tests/*.py`; 86 of them for gate v2: 76 in `test_gate_v2.py` and 10 in `test_agent_gate_v2.py`), `python -m unittest discover -s tests` (no timing given: the agent tests start the real `caladrius-mcp`). CI (`.github/workflows/ci.yml`) runs them on every pull request and push to main, with `optchat` and `caladrius` (main) checked out next to this repository and `caladrius-mcp` built from source; the tests that need `llama-server`, the generated decision datasets or the `datasets` library skip there. Two things live outside this repository: the `caladrius-mcp` binary (`APOTHICAIRE_MCP`) and the `optchat` module of the sibling folder `../optchat` (clone <https://github.com/abdou-rgd/optchat> next to this repository). In a fresh clone without `optchat`, 17 test modules fail to import and only 81 tests run. The per-file counts below date from when the suite held 147 tests.

- `test_digest.py` (23): five frozen `nca_run` answers on PUBLIC data only (theoph subject 1 oral with the dose as an argument and explicit units; indometh IV bolus; edge_blq 6 subjects with BLQ removals and flags; edge_iv with a `no_rise` reason; edge_negative with per-subject errors), each next to the exact tool arguments, and the `tools/list` answer. They assert that `digest_analysis` reproduces every computed parameter as "value unit" at 6 significant digits with an independently written unit table, percentages as `%`, the not-calculated parameters with their reason, λz regression, options, flags, removed points, errors, and that **no number of the digest is absent from the payload**; plus a test that the detector fails when a value is converted or invented, and tests of `_inline` / `to_openai` on the stored schemas. Mutating the rounding or the percent rule in the digest makes 27 and 12 subtests fail.
- `test_gate.py` (42): formats, rounding rule, exemptions, sources, and synthetic sentences built from public golden numbers that reproduce the run-2 hallucinations (CL/F and Vz/F times the dose, times 10^3; six converted values in one answer) and computed differences/percents; the transcripts themselves are not used in any test.
- `test_agent_gate.py` (8): the wiring with a scripted model and the real server: regeneration with the reminder at the end of the messages and nothing before it changed, clean answer = no extra call, badge after a failed regeneration, a worse regeneration not kept, error during regeneration, the memory holding no badge or reminder, the sources of the gate.
- `TestCompareDigest` in `test_digest.py` (8): the digest of `analysis_compare` on a public golden (`tests/golden/compare/`: Theoph subject 1, linear vs lin-up/log-down, generated through the MCP client; the server answers for one parameter and for all 61): one line per parameter "a / b / difference / percent / ratio" at 6 significant digits with units, the rows with no value grouped under their reason, no digest number absent from the payload (and the detector fails on a recomputed difference), the engine's own units win and a unit is never labelled from two different worksheets, the engine's `not_comparable` reasons reproduced, errors passed through, the tool schema and the prompt sentence.
- `test_bench_compare.py` (14): the compare turn once the model has `analysis_compare`. `compare_usage` reads the stored tool calls (which analysis id is which AUC method, the auclast row of the digest) and decides whether the call is usable (the linear and the lin-up/log-down analysis, a row with difference and percentage, equal to the ground-truth arithmetic of meta.json to 5e-5); `resolve_compare` then adds the engine's difference and percentage to the expected numbers and removes them (and the ratio b / a) from the forbidden ones; the percentage of the other reference and a ratio written as a percentage stay forbidden; without a usable call the old strict rule applies unchanged. Both orientations (a = linear or a = lin-up/log-down), eight answer styles for the oracle (sentence, one line, method named in the difference line, table, decimal point, and the three phrasings of the 2026-10-09b run: value before the method label, "valeur absolue", "en valeur absolue"), missing and wrong values, a missing `%`, the stored-record path (`attach_oracle`), the report counts, and one test with the real engine on all 25 exercises.
- `test_nca_route.py` (3): the infusion route (`iv_infusion` + `infusion_duration` becomes the server's route object; a stringified object is parsed; a missing duration is an error text for the model; the real server accepts the result).
- `test_bench_exercises.py` (6): the plan (25 exercises: models, units, BLQ, minutes), the generator is deterministic (two runs byte-identical, equal to the committed CSV and simulation parameters), every committed exercise round-trips through `data_import` + `nca_run` and reproduces the stored oracle values exactly.
- `test_bench_score.py` (13): the scorer (expected numbers with the gate's rounding rule, forbidden values at 3+ digits, words, "not available") and the failure taxonomy on synthetic answers, including the chance baseline of the rules.
- `test_bench_run.py` (9): the 8-turn scripts for all 25 exercises (the truth answer scores correct on every turn, converted / computed answers do not, the "not available" phrasings), `classify_call`, the report arithmetic on synthetic records, and one exercise run end to end with a scripted model and the real server (a conversion in a first draft, fixed by the regeneration).
- `test_bench_oracle.py` (21): the oracle check. The truth answer in three styles (list, table, inline; `·`, `*`, `.` as unit separators; decimal point or comma; `h⁻¹`) is correct on every turn of the 25 exercises; one synthetic answer per class (wrong_parameter, wrong_method, wrong_option only when the value is wrong, missing_unit, wrong_unit, missing_value); the value must follow its label (a right value elsewhere in the answer does not count, where the scorer's global search accepts it); a regression built from the structure of the ex13 / ex07 / ex21 failures with synthetic numbers; the tool-argument audit; the report arithmetic.

Goldens are regenerated by hand with `python tests/make_golden.py` after a deliberate engine change; review the diff. Coursework data never goes into a test or golden file.
