# History: what comes next, what went wrong

The dated status of the decision-model spike, how the code is built, and the known problems with their fixes, moved unchanged from the former README.

## What comes next, and how it is built

**What comes next.** The card `decision/PLAN.md` describes a spike, not finished work: a small decision model (0.8B to 3B parameters) would answer closed questions about the data (which analysis, which route, which AUC method), and a deterministic harness would call Caladrius and write the answer from templates, so that no generated number can exist. The 27B pipeline is kept, and both would run on the same benchmark with the same checks. As of 2026-10-10 (the thread of the card): steps 1 to 5 are done (dataset of synthetic exercises, zero-shot baseline, a trained 0.8B decision model, the harness, scoring on the 25 benchmark exercises: 175 / 175 oracle-correct turns, in distribution), and a second training on a wording-level split (v2) followed. On 74 requests written by a reviewer who had not seen the generator, whole requests right: v1 4 / 74, v2 22 / 74, the 27B on the same closed questions 7 / 74. `bench/NO_LM_ARM.md` pre-registers the decider-only arm of the frozen set (draft of 2026-10-21). The wiring of fit and simulate is not done.

**How it is built, and what went wrong.** The code is written by AI coding agents (Claude Code, and a DeepSeek agent as a second contributor) under a written contract, with a task board and a human who decides what is published. What went wrong, stated in [benchmark.md](benchmark.md) and in the sections below: the first demo showed the model converting units wrongly, and moving a unit label in the digest only moved the problem; a preliminary benchmark run exposed a tool schema the model could not fill in; and the label table of the second check was widened after I read the rerun, so its figure is not out-of-sample.

## Problems found

1. **Unit conversion by the model is the main hallucination source.** As of 2026-10-09: Caladrius only knows the dose unit from a dose column, so with a dose given as an argument CL and V come in `dose unit/(...)` and the 27B converts by itself, wrongly. Fix on the engine side (suggested then): a `dose_unit` parameter for `nca_run` (and the fits) so that Caladrius reports CL in L/h and V in L. Since 2026-10-19 `nca_run` takes `options.units` and the client sends it from the worksheet's units and the model's `dose_unit` (`nca_units` in `apothicaire.py`), so CL and V come in L/time and L when the units are in the engine's table; runs 1-3 and the benchmarks of 2026-10-09 in [benchmark.md](benchmark.md) were made before. The system prompt used to say "if you convert them, show the factor", which invited the conversion the gate then has to catch; since 2026-10-09 it says "quote tool values verbatim and never convert units; if a unit is missing, say so" (runs 1-3 in [benchmark.md](benchmark.md) were made with the old wording).
2. **Unlabelled numbers get misread**: without per-parameter units the model took a percentage for an AUC (run 1). Labelling every parameter with its unit in the digest fixed it. Caladrius could return the unit of each parameter itself.
3. The model still does arithmetic itself (differences, percent changes), right or wrong; the gate reports it. Caladrius now has `analysis.compare` (commit df87aca) and Apothicaire exposes it as `analysis_compare` (see the benchmark rerun of 2026-10-09b in [benchmark.md](benchmark.md)).
4. Turn 4 of run 2 did not exercise the summary memory (compaction only triggers above 12 raw messages); run 1 did, and the model used Caladrius's own project state (`analysis_get`) rather than `zoom` to recall turn 1, which is a good habit.
5. The old number checker of `run_exo1.py` (a relative tolerance let one wrong value match by accident) is replaced by the gate; the transcripts still end with a hand review.
